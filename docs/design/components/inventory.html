Atom + molecule · Inventory

Inventory & Items

Вкладка инвентаря отвечает на три вопроса: что на мне надето, что у меня в котомке, что можно купить или смастерить. Сейчас всё три слоя сразу на экране — 50+ строк одновременно. Решение: что надето / что в котомке — всегда видно (компактным списком), каталог и +свой предмет — по тапу открываются bottom-sheet'ом. В остальном — плоские строки, иконка-дескриптор слева, stat-chip справа, действия мелкими icon-кнопками.

§1

ItemIcon — атом (дескриптор → глиф)

28×28-квадрат с глифом. По умолчанию — muted, у экипированного — золотая обводка и заливка, у расходника — пунктирная рамка (мягкий сигнал «исчезнет при использовании»). Глиф передаёт descriptor.kind: меч / нагрудник / щит / мешочек / молоток / колба / звёздочка.

Состояния по kind

Модификаторы состояния

is-equipped

Почему глиф, а не просто точка-цвет: у игрока 10+ предметов в инвентаре, глиф даёт быстрое сканирование «где мой меч, где флакон» без чтения. Навязчивая цветовая кодировка (зелёный = броня, красный = оружие) создавала бы шум на и так не-монохромной сцене — остаёмся в золотисто-коричневой гамме.

§2

InventoryItem — строка

Одна плоская строка: иконка · имя + описание · stat-chip · actions. Экипированное — с золотой левой полосой и бейджем «надето», поднимается наверх списка. Расходники — вместо equip-тоггла показывают «использовать». Custom-предмет получает дополнительную icon-кнопку «редактировать».

Почему action-иконки, а не kebab: 99% взаимодействий с предметом — «экипировать / снять» или «использовать». Спрятать это за kebab = +1 тап на каждое действие. Удаление — отдельной danger-иконкой с hover-цветом, это достаточно безопасный способ (confirm-диалог остаётся в логике). Edit для custom живёт здесь же, т.к. не-custom предметам эта кнопка просто не показывается.

Бейдж «надето» рядом с именем — избыточность для читаемости: золотая рамка иконки + золотая полоса слева + бейдж. Это оправдано: «что на мне» — самый частый вопрос в бою.

§3

CoinBar — полоса с монетами

Одна тонкая строка сверху вкладки: иконка · лейбл «монеты» · значение (serif-крупно) · ±. Редкое взаимодействие (обычно +1 после продажи лута, −N после покупки из каталога) — значит, кнопок ±1/±10/±100 не нужно, это «плоская» цифра с двумя хоткеями.

default
Монеты 9 529с.
низкий баланс (муар-сигнал)
Монеты 12с.
Попап по тапу на значение — ручной ввод (для обмена «дал −250 за услугу», «нашёл +80 в сундуке»). Цветовой переход при coins < цены самого дорогого каталожного — тонкий warning-оттенок, но без алерта: игрок сам решит, когда фармить.

§4

Inventory screen — всё вместе

Вкладка «Инвентарь» целиком. Сверху — CoinBar. При множественной экипировке оружия/брони — inv-warning. Дальше — секция «Экипировано» (если есть), затем «В котомке». В конце — toolbar с двумя кнопками «Каталог» (bottom-sheet §5) и «+ Свой предмет» (§6).

Почему секция «Экипировано» отдельно: это то, что игрок читает в бою — надо видеть сразу. Без отдельной секции equipped-строки «всплывают» наверх сортировкой, но смешиваются с лутом. Отдельный заголовок «Экипировано · 3 · урон d6+1 · броня 3» — это ещё и итоговая строка по экипировке, не надо считать в голове.

Инструменты (tool) не экипируются — лежат в «В котомке» без toggle, но с delete. По спеке инструменты тоже могут быть equipped — если нужно, поведение просто такое же, как у оружия.

§5

Catalog — bottom-sheet

Открывается из toolbar'а. Sticky-поиск сверху, segmented с 7 категориями, плоский список товаров. У доступных по цене — «купить», у недоступных — цифра цены подсвечена warning'ом и кнопка ведёт на диалог «не хватает монет» (§7). Текущие монеты справа в шапке, чтобы игрок всегда видел, сколько есть.

«Спросить» вместо «Купить» у дорогих предметов — открывает §7-диалог («попроси мастера»). Игрок не застревает на «не хватает», видит прямой путь вперёд. Цена в warning-цвете подсказывает, что покупка невозможна обычным путём.

Группировка — по категории (segmented), но внутри группы порядок по цене от дешёвого к дорогому (а не алфавит). Игрок на низком балансе сразу видит, что доступно, не скроллит мимо «Полного доспеха за 60с».

§6

Custom item form — bottom-sheet

Отдельный лист, а не inline-форма на вкладке (как сейчас). Поля из спеки: имя · цена · описание · расходник · количество. «Количество» показывается только когда «Расходник» отмечен. Submit — btn-hero «Добавить». Та же форма в режиме edit — с заголовком «Редактировать» и доп. кнопкой «Удалить».

+ Свой предмет
Редактировать · расходник
Одна форма в двух режимах (create / edit) — отличается только заголовком, наличием кнопки «Удалить» и кнопкой submit («Добавить» / «Сохранить»). «Количество» — условное поле: показывается, только если «Расходник» отмечен. В текущем ДО — отдельная панель на вкладке + 4 поля всегда, без условности.

§7

Недостаточно монет — диалог

Появляется при покупке дорогого (coins < price) — из §5 при нажатии «Спросить» или если игрок всё же жмёт «Купить» на недоступном. Три исхода: попросить мастера (RECEIVE_ITEM), попробовать скидку, отмена.

Не хватает монет
«Полный доспех» стоит 60 с.
У тебя 152 с. — не хватает 408 с.
Хочешь обратиться к мастеру за предметом или попробовать договориться о скидке?
«Торговаться» — это бросок на ВЛИ, который может снизить цену (решение мастера). Логика игровая, для дизайна важно: три варианта, у каждого разный вес. «Попросить мастера» — btn-hero (это предполагаемый путь), «Торговаться» — btn-primary (опционально), «Отмена» — ghost.

§8
